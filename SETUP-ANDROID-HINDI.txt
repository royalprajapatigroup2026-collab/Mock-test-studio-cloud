MOCK TEST STUDIO — PUBLISHER + CLOUD SYNC (TEST PACKAGE)
=======================================================

WHAT THIS PACKAGE ADDS
- publisher.html: Android-friendly page to paste Gemini JSON, validate, review and approve.
- netlify/functions/api-questions.mjs: authenticated publishing endpoint and public read-only sync feed.
- Netlify Blobs: stores each approved batch in cloud storage.
- Mock Test Studio home: Sync Published Questions button and Publisher link.
- Sync is additive. It appends approved merge/new records; it does not replace the Question Bank.
- Existing local question bank, results, bookmarks and settings are not deliberately cleared.
- Batch IDs prevent the same cloud batch from being imported twice on the same device.

IMPORTANT: THIS IS A TEST DEPLOYMENT PACKAGE
Do not upload this over your live site as the first step. Deploy it to a separate Netlify test site first. Your existing live site is unchanged by this package.

REQUIRED NETLIFY DEPLOY METHOD
Netlify Functions need a build deployment. A simple drag-and-drop static ZIP upload is not sufficient to build these functions.
Use a Git-connected Netlify site/repository (recommended) or Netlify CLI. Android-only users can create a new empty GitHub repository in the GitHub mobile website, upload the extracted package files to its root, then connect that repository to a NEW Netlify test site.

SETUP STEPS
1. Create a NEW GitHub repository for testing. Do not use FactoraStudent2; it is a separate project.
2. Upload all files/folders in this package to the repository root. Ensure index.html, publisher.html, package.json and netlify.toml are at the root.
3. In Netlify, create a NEW site by importing that GitHub repository.
4. Build settings: Publish directory = . ; Functions directory = netlify/functions. The netlify.toml already specifies these values. Leave the build command empty unless Netlify requires one.
5. In the NEW Netlify test site's Site configuration → Environment variables, add:
   Key: PUBLISHER_TOKEN
   Value: create a long random secret (at least 32 random characters).
   Save, then trigger a fresh deploy so the function receives the variable.
6. Open https://YOUR-TEST-SITE.netlify.app/publisher.html on Android Chrome.
7. Paste the PUBLISHER_TOKEN into the Publisher page's token field. Paste a Gemini JSON bank, tap Validate & Preview, choose Merge and type the exact subject name (e.g. Computer Awareness), or choose New subject.
8. Tick the approval checkbox and tap Approve & Publish to Cloud.
9. Open the test PWA homepage and tap Sync Published Questions. The app checks the local target and answer conflicts before saving. If questions were added, it reloads to activate them.

JSON REQUIREMENTS
- Top level: subject (or name) and chapters array.
- Each chapter: title and questions array.
- Each question: question text, options A/B/C/D (all non-empty), and one answer key A/B/C/D.
- Multiple-correct answer arrays are not supported by this PWA version.
- Optional fields such as explanation, source, difficulty, tags and verification_note are retained by the app's importer.

SAFETY / LIMITATIONS
- Keep PUBLISHER_TOKEN private. It belongs only in Netlify Environment Variables and the Publisher page password field. Never put it into index.html, GitHub source, a public note, or a chat.
- The cloud feed is read-only for the PWA; only a request with the secret token can publish.
- If a batch targets a subject that does not exist on a device, or if duplicate subject names / answer conflicts exist, sync skips that batch and reports the issue. It does not guess.
- Sync runs when the user taps the button. It does not silently run in the background while the app is closed.
- Back up Mock Test Studio from its Full Backup feature before testing. Keep the backup file somewhere safe.
- First test with a small JSON batch (2–5 questions), verify it appears correctly, and test duplicate sync (it should not add the same batch again).
- Do not replace the original live site until the separate test site passes all checks.

ROLLBACK
The original live site has not been changed by preparing this package. If a test deployment behaves incorrectly, stop using the test site and continue using the original site. Local question data is browser storage scoped to the site's origin; the test site's storage is separate from the original site's storage.
